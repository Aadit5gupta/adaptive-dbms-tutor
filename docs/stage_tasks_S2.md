# S2 task checklist

[The master plan](../MASTER_PLAN.md) defines S2 acceptance. Run the structural validator and rerun the learner demo and relevant migration tests after changes.

| Task | Files | Acceptance |
|---|---|---|
| S2.1 Resumable allocation and screening | Assessment and curriculum services, session tests | Five-question practice persists across refresh. Previously exposed items sort behind fresh ones. A diagnostic screens reviewed domains and supports distinct follow-up probes. |
| S2.2 Recommendation and review | Adaptive and learner-state services, simulation tests | Available difficulty, real prerequisites and review timing inform stored decisions. Repeated questions add no independent confidence. Exhaustion has an explicit explanation. |
| S2.3 Progress data and boundary tests | Progress service, demo, test report | Coverage and review-due details reflect persisted evidence. Re-run browser A/B and the strict validator. Document the actual stage gate and any human review blocker. |

Synthetic fixtures stay confined to tests. Stage exit retains the requirements for an approved learner demo.
